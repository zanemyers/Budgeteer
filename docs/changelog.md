# CHANGELOG

## 2026-08-12

### Fixed

* **The Banking page was unusable on a phone, and mislabelled half its accounts.** Fourteen account cards, each rendering a payment-method dropdown with a hard `min-w-[260px]` — wider than a 390px phone's content column once card padding came off it — and every account without a payment method read "— Not in any budget —". That last part was wrong for four of them: an account SimpleFIN returns holdings for *is* the Investments page's source (`Holding.bank_account` is the link; there is nothing to map), so it was reading identically to an account doing nothing at all. Cards are now collapsed to name, balance and a one-line role — the mapped payment method, `Investments · N positions`, or a quiet *Not used* — with the dropdown, recent transactions and Hide behind a tap. New `holdings_count` on the serializer, counted via `len()` off a new `bank_accounts__holdings` prefetch so it doesn't re-query per account. Page height at desktop width went 3747px → 1316px, and nothing overflows at 390px in either state.

* **The dashboard goals card scrolled sideways.** `TableCell` hard-codes `md:whitespace-nowrap`, so from `md` up no cell may wrap — and this card sits in the `md:col-span-4` sidebar while carrying three figure columns. One 50-character goal name was therefore setting the column's min-content width and dragging the table 68px past its container even at 1280px. The goal name now wraps (applied to the inner link/button, not the cell: a competing `md:whitespace-normal` on the same cell would be resolved by Tailwind's internal property ordering rather than source order), which takes the table from 383px to 279px. That still doesn't fit the 224px column at the `md` breakpoint itself, so **Saved** folds under the goal name between `md` and `xl` and returns as its own column above it. `lg` was measurably too early — at 1024px the sidebar is ~290px and three figure columns still want ~340px. Verified at 390/500/768/900/1024/1200/1280: zero overflow at every width, and the Income and Expenses cards were never affected.
* **`VITE_MANIFEST_FILE` pointed inside `STATIC_ROOT`, where `collectstatic` can never put it.** staticfiles ignores `.*` by default and Vite emits `.vite/manifest.json`, so the file was silently skipped and `collected_static/dist/js/.vite/` was left an empty directory. The only mode that reads the manifest is `VITE_DEV_MODE=False`, which is the one mode nobody had ever run — so with `DEBUG=False` the first `vite_asset` call raised `FileNotFoundError` and took **every page** down. Now read from Vite's own `outDir`, which ships in the repo and any built image, and keeps the manifest out of the publicly served tree even when static files go to S3. Pinned by a test asserting the setting is not under `STATIC_ROOT` and does match `vite.config.mjs`'s `outDir`.
* **The onboarding tour highlighted the off-screen sidebar on a phone.** Steps were filtered on whether their anchor was *present*, but below `lg` the sidebar is a drawer held off-screen with `visibility: hidden` — present, so every sidebar-anchored step survived and driver.js dutifully spotlit something invisible. Since the full run auto-starts on the dashboard for `onboarding_completed=False`, that was the first thing a new account saw on the primary target device. The filter now requires visibility, and the "Your budgets" step falls back to the mobile header's menu button (`data-tour="nav-menu"`), which is where navigation actually lives at that width.
* **Three dark-mode contrast failures, all the same mistake** — a literal `text-white` on a token that inverts to roughly 72% lightness in the dark theme. The date-range picker's selected day (`bg-moss text-white`) measured **2.41:1**, the transaction modal's Expense segment (`bg-destructive text-white`) **2.84:1**, and its savings-fund segment (`bg-amber-500 text-white`) **2.15:1 in both themes** — that last one the only off-token colour anywhere in the JSX, sitting beside `--fund`, the warm-earth token that already meant "goal deposit". Now on their paired foregrounds at 8.14:1, 6.92:1 and 8.69:1. shadcn's own destructive `Button` and `Badge` keep `text-white` and are correct: they pair it with `dark:bg-destructive/60`, which composites against the dark `--paper` to 5.69:1 — the absence of that dark variant is exactly what made the modal wrong. New `--fund-foreground`, aliased to `--moss-foreground` the way `--destructive-foreground` already was.
* **The 404 and 500 pages rendered a broken pre-Inertia shell.** Both extended `layouts/base.html`, which included `blocks/nav.html` — Bootstrap 5 markup, long after Bootstrap stopped being a dependency. 17 undefined layout classes (`offcanvas-lg`, `d-none`, `d-lg-flex`, `flex-grow-1`, `btn-close-white`, `border-top`) and three dead `data-bs-*` hooks, so the sidebar neither hid nor positioned itself and its account dropdown did nothing when clicked — on the one page a lost user actually sees. The content was bare unstyled `<h1>Page Not Found</h1>`, and the 500 title read "Ooops...." with four dots. Both now extend a new `layouts/standalone.html` with real copy and a route back into the app.
* **Allauth's Email addresses and Password pages were reachable and off-design.** `/accounts/email/`, `/accounts/password/change/` and `/accounts/password/set/` were never shadowed in `config/urls.py`, so they fell through to Allauth and rendered a second, older account UI on that same broken shell — duplicating rows `AccountSettings` already owns. Now redirects to `account_settings`, with the URL names kept so Allauth's internals and links in already-sent emails still resolve.
* `alert-error` and `alert-info` had no CSS at all. `layouts/base.html` emitted `alert alert-{{ message.tags }}` while `main.css` defined only `-success`, `-danger` and `-warning`, so two of Django's five message tags rendered unstyled. Gone with the template.

* **Modals were unusable with the software keyboard up.** `DialogContent` centres with `translate-y(-50%)` against the *layout* viewport, which a keyboard does not shrink — it just draws over the lower half, hiding the field you tapped. Below `sm` the dialog now takes the whole screen (`inset-0 h-dvh`) and `DialogFooter` is `sticky bottom-0`, so the keyboard only covers the bottom of a scroll container (the browser scrolls the focused input into view itself) and Save stays reachable without scrolling past every field. No `visualViewport` JS, no dependence on `interactive-widget` support. Desktop is unchanged from `sm` up. Side effect: short confirm dialogs are full-screen too.
* **`TransactionModal` was nine stacked fields on a phone.** Category and amount promoted to a row under the description; note, payment method and currency share one row; the repeating line-item editor and its heading only appear after tapping *Split across categories*; split rows stay on one line at every width. The currency trigger shows just the code (children passed to `SelectValue` override the trigger while the list keeps full names).
* **Row action menus said "Edit recurring transaction".** Bare verbs now — the menu hangs off the row it acts on, and the noun only widened it until it overhung the screen edge. `w-60` → `w-40`; the noun survives in the confirm dialog title.
* **The bank-row suggester proposed a hidden system category** — "Create in Transfers — Suggested 85%". The merchant rule learns categories from previously linked bank rows, and the retired confirm-as-transfer flow wrote its lines into the system "Transfers" category, so that history kept scoring after the code was removed. It now skips `is_system` categories: a category hidden from every user-facing list can never be a valid suggestion.
* **Rows left in the hidden Transfers category** (`0004_retire_transfers_category_rows`). `0002` only saw *paired* legs; these were single legs from the "link against an existing transaction" path, which had no `transfer_partner` to match on. They were also a wrong number, not just clutter — `derive_transaction_type()` falls back to the line's category type when `transaction_type` is blank and that category is `TYPE_EXPENSE`, so the bank-backed ones counted as real expense spending somewhere no screen would show. Same split as `0002`: bank-backed rows deleted and their bank rows returned to `pending` for the Ignore flow; rows with no bank row left alone as the only record that money moved.

### Added

* The pig logo beside the brand in the mobile header, reusing the sidebar's two-image light/dark swap. The mapping is inverted from the sidebar's on purpose: that sits on moss in both themes and wants the white pig in light mode, while this header is `bg-background` and needs the black one.
* **Self-hosted Inter**, in two `unicode-range` subsets under `src/fonts/`: `latin` (73 KB, every page) and `latin-ext` (134 KB, which carries the `U+20A0-20C0` currency block — ₹ ₽ ₩ ₪ ₫ — so a dollars-only budget never fetches it). Google Fonts cost a preconnect to two third-party hosts and two serial round trips before any text could be styled, so the first paint reliably flashed system-ui and reflowed. Vite hashes and emits the files, which puts them under the service worker's cache-first asset prefix and into its precache list for free. New `{% vite_font_preload %}` preloads only the latin subset — with `crossorigin`, since a font is always fetched in CORS mode and a mismatched preload is discarded and refetched. 48 of the 162 symbols in `currency_symbols.csv` need glyphs outside both subsets (Arabic, Cyrillic, Thai); those fall back to a system face exactly as they did before, since Inter has no glyphs for them either.
* **A re-linked bank no longer produces a duplicate account.** SimpleFIN identifies an account by an opaque id and `sync_simplefin` upserts on `(connection, simplefin_id)`, so re-linking a bank the bridge is struggling with — which hands back a *new* id for an account you already had — created a second row rather than updating the first. The old row froze at its last sync while keeping its transactions and its payment-method mapping, and every account list showed both. Sync now adopts the existing row when two things hold: exactly one account on that connection matches on name and institution, **and** its id has vanished from the payload being processed. The second condition is what makes it safe — an account the bridge still reports is a live account that merely shares a name, and folding those together would merge two real accounts. Ambiguous cases (two stale candidates) still create a row and leave it for a human.
* **`merge_duplicate_bank_accounts`** cleans up pairs that predate that fix. It moves transactions, holdings and balance snapshots onto the row the bridge is still reporting — skipping any the keeper already holds, since `(bank_account, simplefin_id)` is unique — carries the payment method across if the keeper lacks one, then deletes the stale row. Carrying the mapping is not cosmetic: `BankTransaction.for_budget` reaches a budget *through* the payment method, so dropping it would take every one of that account's transactions out of the register. Dry-run by default; `--apply` to write.
* **iOS no longer zooms the viewport when you tap a text field.** Safari zooms in on a focused field under 16px and does *not* zoom back out, leaving you at a magnification the layout was never designed for, scrolling sideways to read a row. shadcn already guards this by putting `text-base` on `Input` and `Textarea` — but `text-base` is `1rem` and this app sets `:root` to `0.9375rem`, so every field rendered at **15px** and zoomed anyway. A `@media (pointer: coarse)` rule now pins `input`, `select` and `textarea` to a literal 16px. It's deliberately unlayered, since Tailwind's utilities live in `@layer utilities` and unlayered CSS beats any layer — which is what stops the primitives' own `md:text-sm` re-breaking it on a coarse-pointer tablet, where `md` is very much active. The usual workaround, `maximum-scale=1` on the viewport meta, was not used: it fixes the zoom by disabling pinch zoom entirely, which is a worse accessibility failure than the one it solves.
* **The landing page has no theme toggle.** Its header's job is Sign in and Sign up, and a third control never sat cleanly beside them for a preference that costs nothing to leave alone: the pre-paint script in `app.html` already applies whatever is in `localStorage`, and the default `auto` follows `prefers-color-scheme`, so a visitor gets their system theme without being asked. The toggle is waiting in the sidebar once they're signed in. (`AuthLayout` — sign in, sign up, password reset — keeps its own; those are centred cards with room to spare rather than a crowded header.)
* **Bulk actions on bank rows follow the tab.** The Ignored tab now offers **Restore** first and no longer offers Ignore; the pending tab offers Ignore and no longer offers Restore. They were mirror images and each other's action was meaningless — a row on the Ignored tab is already ignored, one awaiting review is already pending — which left the useful one sitting second on the tab where it was the only thing you'd want. "Restore to pending" is just **Restore**; where the rows go is said in the confirm dialog, which has room for it. Switching tabs now also clears the bank selection: the comment beside that handler already said a selection must not survive a switch, but only the transaction set was being cleared, and with the actions differing per tab that would have meant acting on invisible rows with the wrong tab's actions.
* **The Ignored tab lost a column that only ever said "Ignored".** Every row's Category cell read the same word the tab already says, so the column is gone. Below `sm` the ignore reason goes too — it's a note to yourself, not something to read at a glance — along with the Actions column, whose bare undo arrow floated vertically centred against a two-line cell saying neither what it did nor where the row would go. Restoring on a phone is a bulk-select action now, which the selection bar already offered; from `sm` up the icon column is unchanged. The amount on both bank rows also moved from `items-start` to `items-center`, since it belongs to the row rather than to the payee line and was left hanging above the date.
* **The Transactions filter button is icon-only, and the panel behind it is a real panel.** The word "Filters" was taking 80px of a 390px row; the button is now 34px and the search field gained 47px. The active count it used to spell out becomes a badge on the icon's corner — the one thing the label carried that an icon can't, since a narrowed list otherwise looks like an empty one, and `aria-label` says it in full either way. Opening it below `md` now gives a framed, tinted panel of labelled rows (Category / Method / Days) with **Clear all** in its header, rather than three loose full-width controls dropped into the page. The labels earn their place once a filter is set and the trigger reads "Eating Out" instead of "All categories". From `md` up the frame, the header and the label rows all dissolve via `md:contents` back into the single wrapping row the desktop layout already used — verified unchanged at 1280px, all three controls still on one line at 180/160/75px.
* **The Banking page groups by what an account is for, not by which connection served it.** Three sections — *In your budget*, *Investments*, *Not used* — replacing a per-connection heading that, with one connection, was a single heading over everything. A payment method outranks holdings when deciding the group: an account can be both, and a savings account paying a couple of bills belongs with the money you budget from. Connection health moved above the accounts, since it describes the pipe rather than any one account and an unhealthy connection's accounts now sit across several sections.
* **The pending badge only appears where it can be acted on.** It counts bank rows awaiting review, but `for_budget` reaches a budget through `bank_account__payment_method__budget` — so on an account mapped to no budget those rows never reach the pending tab and nothing can ever clear them. Schwab alone advertised 31, and the page header claimed "37 pending transactions" when every one of them was unreachable.
* **Hiding a bank account.** `is_hidden` had been on the model, in the serializer and accepted by `BankAccountUpdateView.patch` — with three tests — since it was added, but nothing read it and no UI set it. Now there's a Hide action on the expanded card and a collapsed **Hidden (N)** section at the foot of the page to undo it; hidden accounts are still sent from the server, since filtering them out there would strand one with no way back. The header counts follow what's on screen, or you'd get "14 accounts · 37 pending" above a page showing five and no pending at all. Hiding is display-only: an account with no payment method is already invisible to every budget, because `BankTransaction.for_budget` reaches a budget *through* one.
* **The onboarding tour loads on demand.** `driver.js` and its stylesheet are ~25 KB of JavaScript plus 3 KB of CSS that only matter once a tour runs, but `AppLayout` imports the tour module on every page for the "Replay tour" menu item, so a static import parked the whole library in the shared entry chunk — the logged-out landing page was downloading it. The `DriveStep` import is now type-only (erased at build time) and the library is imported inside `runStage`. A run token guards the gap: `endActiveTour` bumps it so a load still in flight when the page unmounts is dropped rather than stranding an overlay, which is the same failure the `activeTour` handle exists to prevent. `main.css`'s `.driver-popover.budgeteer-tour` rules are more specific than driver.css's, so they still win regardless of stylesheet order.
* **Per-page code splitting.** `main.tsx` dropped `eager: true` from its `import.meta.glob`, so each page is its own chunk instead of all sixteen sharing one. A visitor on the public landing page was downloading the whole authenticated app: **220 KB gz → 163 KB (-26%)** for Landing, and 195 KB (-12%) for Transactions, the heaviest. `resolve` returns `module.default` rather than the module — Inertia's `ComponentResolver` accepts a component, a promise of one, or a synchronous `{ default }`, but not a promise of a module. New `{% vite_modulepreload %}` emits `modulepreload` links for the entry's static-import closure, which Vite injects itself only into HTML it generates; without it splitting would have cost a serial round trip before the shared chunks were even discovered.
* `VITE_SERVER_HOST` (env-driven, default `localhost`) — the host the browser fetches Vite dev assets from, so the app can be opened on a phone over the LAN. Paired with `ALLOWED_HOSTS`, and `vite.config.mjs` now extends Vite's `defaultAllowedOrigins` with `192.168.x.x`, since Vite sends `Access-Control-Allow-Origin` to localhost origins only and module scripts are always CORS-mode fetches. See [Architecture → Opening the dev app on a phone](architecture.md#opening-the-dev-app-on-a-phone). `test_runner.py` pins the setting so the templatetag tests don't depend on a developer's `.env`.

### Removed

* **The entire pre-Inertia UI shell**, ~550 lines that nothing signed-in had rendered for months. Gone: `layouts/base.html`, `blocks/nav.html`, `blocks/color_mode_picker.html`, `blocks/inline_crud.js`, `account/base_entrance.html` and nine `account/*.html` templates, plus the `.btn*` / `.form-control` / `.form-label` / `.text-danger` / `.text-secondary` / `.alert*` block in `main.css`. That CSS block's comment claimed it kept "edge Allauth templates from looking totally broken", but Allauth emits bare HTML through its `{% element %}` tags and never carried those class names — only our own retired copies of the auth templates did, so it was styling nothing that still existed. Replaced by element-scoped `.standalone` rules, which cover any Allauth page including ones a future version adds. `account/logout.html` was dead regardless: `ACCOUNT_LOGOUT_ON_GET = True` means that view never renders a template.
* `layouts/base-email.html` and `base-email.txt` — HTML 4.01 scaffolding with nothing rendering them; no `render_to_string` call anywhere and Allauth ships its own email templates. The djLint `exclude = "base-email.html"` that existed to tolerate them went too.
* `django-vite` — unused. The project has its own `apps/base/templatetags/vite.py`, which is what `{% load vite %}` resolves to (django-vite's tag library is named `django_vite`, so there was never a collision); `{% load django_vite %}` appears nowhere. Its only effects were a startup system check that warned about a manifest path nothing read, and a `DJANGO_VITE` settings block duplicating `VITE_SERVER_HOST`/`VITE_SERVER_PORT` with a stale hard-coded `localhost`. Surfaced by the `DEBUG=False` smoke pass, which is the only place that warning appears.
* `components/ui/progress.tsx` — zero importers. (`showProgress: true` in the tour is driver.js's own option, unrelated.)
* **Transfers (two-leg pairing)** — retired the whole feature added on 2026-07-23. Gone: `Transaction.transfer_partner` and its column, `link_transfer()` / `unlink_transfer()`, `Category.get_or_create_transfers()`, the three candidate-matching helpers in `data.py` (`find_transfer_candidates`, `find_pending_bank_transfer_candidates`, `find_transfer_candidates_for_bank_txn`), the `TransferCandidatesView` / `TransferLinkView` / `BankTransactionConfirmAsTransferView` views and their three routes, the `is_transfer` and `transfer_partner_id` serializer fields, and all user-facing "transfer" wording. An account-to-account movement is handled by **ignoring the bank row** instead — simpler, and nothing has to be kept in step.
* Migrations: `0002_retire_transfer_pairs` unpairs every row, deleting bank-backed legs and returning their bank rows to `pending` (the bank row still carries date, payee, amount and memo, so nothing is lost) while leaving hand-entered legs in place; `0003_drop_transfer_partner` removes the field.

### Changed

* `transaction_type="transfer"` **stays**, now meaning exactly one thing: a goal deposit. The ready-to-assign and goal-balance sums in `data.py` still exclude it, so money moved into a goal reads as neither income nor spending. The Transactions page badge reads **Goal** rather than Transfer, and the goal modal is titled "Deposit to Goal".
* `test_transfers.py` replaced by `test_goal_deposits_do_not_distort_totals.py`, covering the invariant that outlived the feature.
* `test_design_token_contrast.py` gained three checks: every saturated background has a readable paired foreground, no `text-white` sits on a brand background without a `dark:` override, and no numbered Tailwind palette colour appears in the JSX. The existing tests only compared token against token, which is why they read clean while three real failures shipped — the palette was fine and the JSX simply wasn't using it.
* Banking's **Sync now** is an icon button — the page's only action, and the label bought nothing at 390px. `aria-label` and `title` carry the name, and the icon spins while a sync is in flight so the disabled state reads as working rather than broken.
* The offline page now uses Inter. It deliberately links no stylesheet — it renders when the network is unreachable — but the font is self-hosted and precached, so it declares its own `@font-face` against the hashed subset via a new `{% vite_font_url %}` tag. `font-display: swap`, not `block`: if the worker's cache has it either behaves identically, and if it doesn't, `block` would hide the text for three seconds on the one page whose job is explaining what went wrong.
* `BudgetSettings`' compact tab picker keeps its native `<select>` (the right control below `md`) but is styled with the same tokens as `Input` instead of the retired `.form-control`.

## 2026-07-23

### Added

* **Transfers** — first-class account-to-account movements. A new `transfer_partner` 1:1 self-FK on `Transaction` links two legs; both are excluded from headline income/expense totals. A hidden per-budget "Transfers" category (`Category.is_system=True`, `Category.get_or_create_transfers()`) holds the placeholder line. New `BankTransactionConfirmAsTransferView` lets you confirm a bank row against another pending bank row or an existing transaction, creating and linking the pair. Transactions page adds a **Transfers** tab; frontend uses a computed `is_transfer` serializer flag that folds in three signals (`transaction_type == "transfer"`, `transfer_partner` set, or any line in a system category) so orphan/legacy transfers no longer leak into the Logged tab.
* `jsonFetch` now surfaces expired-session redirects (`/accounts/login/`) as a structured `{ error, status: 401 }` throw instead of a confusing `SyntaxError`.

### Fixed

* `AssignModal` batch-assign now uses `jsonFetch` (throws on non-2xx) instead of raw `Promise.all(fetch(...))`, which silently accepted 4xx/5xx as success and left partial assignments unsaved.
* Every mutation in `Transactions.tsx` (`saveDesc`, `saveDate`, `savePM`, `markPaid`, `deleteTxn`, `restoreBankTxn`, `ignoreBankTxn`, `ignoreLinkedBankTxn`, `saveIgnoreReason`) is now wrapped in `try/catch` with a `sonner` toast on failure. Previously errors were silently swallowed.
* Confirming a bank row as a transfer against another pending bank row now removes **both** rows from the Pending list immediately (was leaving the partner behind until page refresh).

### Changed

* Retired the leftover MkDocs stack (`config/mkdocs.yml`, `lint_docs` recipe, four direct + ~20 transitive deps). Zensical is now the sole docs generator.
* Deleted four empty scaffold apps (`apps/billing/`, `apps/notifications/`, `apps/organizations/`, `apps/teams/`) — never in `INSTALLED_APPS`, never imported.
* CLAUDE.md, README.md, and the docs site now correctly reflect the current apps list (`accounts, base, budget, banking, investments`), settings modules (`_base.py`, `test_runner.py`), and toolchain (Biome for JS/TS/CSS, not ESLint/Stylelint).
